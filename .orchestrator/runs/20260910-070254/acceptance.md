## A. 애정운 — 백엔드

### A1. 계약이 타입으로 고정된다
`lib/types.ts`에 `IdealPartner`, `Romance`, `LoveReading`이 있고 `FaceReading.love`가 필수다.
- 검증: `tsc --noEmit` 통과

### A2. 프롬프트가 애정 스키마를 지시한다
`buildAnalysisPrompt()`가 `love`, `idealPartner`, `type`, `traits`, `reason`,
`romance`, `tendency`, `fortune`, `caution`을 **문자 그대로 포함**한다.
- 검증: 키 배열을 **순회**하며 단언

### A3. ★ 외모 평가 가드레일이 프롬프트에 있다
프롬프트가 어울리는 상대를 **성향·분위기**로 기술하라고 지시하고,
**외모의 우열·등급을 매기지 말라**고 명시한다.
- 검증: 테스트가 가드레일 문장의 존재를 단언 + 오케스트레이터가 프롬프트 전문을 **눈으로 읽고** 판정
- **게이밍 방지**: 키워드만 끼워넣고 실제 지시가 없으면 실패. 문장이 실제로 그 뜻인지 사람이 읽는다.
- 근거: 이 기능은 "어떤 사람이 너와 어울린다"를 말한다. 외모 서열로 흐르면 재미가 아니라 해가 된다.

### A4. 파서가 애정 필드를 검증한다
`parseAnalysis`가 `love.idealPartner`(type·traits·reason)와 `love.romance`(tendency·fortune·caution)를
모두 갖추고 문자열이 비어있지 않을 때만 `kind:'ok'`를 낸다. `traits`는 문자열 배열이며,
문자열 하나가 오면 배열로 감싼다. 하나라도 빠지면 `unparsable`.
- 검증: 정상 / love 통째 누락 / romance만 누락 / traits가 문자열 — 4케이스 독립 테스트
- **게이밍 방지**: 값이 비어있지 않음까지 단언한다. 필드 존재만 보면 빈 문자열로 통과한다.

### A5. 스프린트 2 회귀 없음
기존 features·personality·saju 테스트가 전부 그대로 통과한다.
- 검증: `npm test` fail 0 (기존 119건 포함)

## B. 결과 임시 저장 (localStorage)

### B1. 저장/복원/삭제가 주입된 Storage로 테스트된다
`lib/storage.ts`의 함수들이 `Storage` 유사 객체를 **주입받아** 동작한다
(모듈 최상위에서 `localStorage`를 만지지 않는다 — 서버 렌더 시 죽는다).
- 검증: 가짜 Storage로 저장 → 복원 → 값 일치 테스트

### B2. 큰 미리보기는 이미지를 빼고 저장한다
`MAX_SAVED_PREVIEW_BYTES`(1MB) 초과 시 `preview: null`로 저장하고 결과는 보존한다.
- 검증: 1MB 초과/이하 각각 테스트

### B3. 못 믿을 저장분은 조용히 버린다
아래 각각에서 `loadResult`가 **예외를 던지지 않고** `null`을 반환한다:
저장 없음 / JSON 아님 / `version` 불일치 / `result` 구조 불량
- 검증: 4케이스 독립 테스트

### B4. 저장 실패가 앱을 죽이지 않는다
`setItem`이 `QuotaExceededError`를 던져도 `saveResult`가 예외를 밖으로 내지 않는다.
- 검증: 던지는 가짜 Storage로 테스트

### B5. 새로고침해도 마지막 결과가 보인다
- 검증: **브라우저** — 결과 렌더 → 새로고침 → 결과가 다시 보임

## C. 카메라 입력

### C1. 업로드/카메라 선택 UI가 있다
초기 화면에 두 입력 수단을 고르는 컨트롤이 있다.
- 검증: **브라우저** `read_page`에 두 선택지가 존재

### C2. 카메라 전환 시 스트림을 요청하고, 촬영하면 분석 흐름을 탄다
- 검증: **브라우저** — `navigator.mediaDevices.getUserMedia`를 가짜 스트림으로 스텁 →
  카메라 탭 → 비디오 요소 등장 → 촬영 버튼 → 미리보기 생성 확인

### C3. 권한 거부 시 안내가 뜨고 업로드로 되돌아갈 수 있다
- 검증: **브라우저** — `getUserMedia`가 `NotAllowedError`로 reject하도록 스텁 →
  안내 문구 노출 + 업로드로 복귀하는 컨트롤 존재

### C4. ★ 카메라를 끄면 스트림이 실제로 멈춘다
업로드로 전환하거나 촬영을 마치면 모든 트랙의 `stop()`이 호출된다.
- 검증: **브라우저** — 가짜 트랙의 `stop` 호출 횟수를 세어 1회 이상 확인
- 근거: 안 끄면 카메라 표시등이 계속 켜져 있다. 사용자가 감시당한다고 느낄 수 있는 실제 문제다.
