### 에이전트가 스스로 밝힌 판단 지점 — 검토 결과

명세 게이밍은 발견되지 않았다. 다만 사용자가 알아둘 만한 것 셋:

1. **오류 상태코드 일부는 원칙으로 유추한 값이다.** 테스트는 4xx/5xx 대역만 강제했고,
   `NO_FACE=422`, `UNPARSABLE_RESPONSE=502`는 구현자가 "입력 오류 4xx / 업스트림 5xx" 원칙을
   적용해 정했다. 원칙에 부합하지만 명시된 값은 아니었다.
2. **`extractJsonBlock`은 첫 `{`에서 한 번만 시도한다.** 그 구간이 파싱에 실패하면 다른 `{`로
   재시도하지 않고 `null`을 낸다. 테스트 범위에서는 충분했으나 이론적 사각지대다.
3. **오류 화면의 "다시 시도"는 미리보기를 지우지 않는다** (결과 화면의 "다시 분석하기"는 지운다).
   타임아웃 같은 경우 같은 사진으로 재시도하기 편하게 한 의도적 설계다.
   → 다만 `NoFaceNotice`의 버튼 문구는 **"다른 사진으로 다시 시도"**인데 실제로는 이전 사진이
   그대로 남는다. **문구와 동작이 어긋난다.** 아래 "다음 제안" 참조.

## 차단된 것 — 사용자가 직접 해야 할 일

### 1. 응답 시간 5초 이내 실측 (DoD 항목)
실측하려면 실제 Gemini 호출이 필요하고, 이는 **안전경계 4(유료 API 호출 금지)**에 걸린다.
`.env.local`에 실제 키가 있어 기술적으로는 가능했지만, 자리를 비운 사이 과금을 발생시키는 것은
되돌릴 수 없다고 판단했다.

**하는 법**: 앱을 띄우고 사진을 올리면 성공 응답 본문에 `elapsedMs`가 들어 있다.

### 2. 브라우저 실행 검증 (B5·B6의 검증 등급이 내려간 이유) ★
**샌드박스가 포트 바인딩을 막는다.** `next dev`가 `listen EPERM: operation not permitted`로
기동하지 못했다. 승인 창을 띄우면 무인 주행이 그 자리에서 멈추므로 뚫지 않았다.

그래서 UI 검증을 **`renderToStaticMarkup` 실렌더**로 대체했다. 이것으로 B1·B2·B3·B4·B8은
실제 렌더 결과로 판정할 수 있었지만, **이벤트 핸들러가 필요한 B5(파일 선택)·B6(초기화 클릭)은
실행할 수 없었다.** `jsdom` 등 DOM 구현체도 설치되어 있지 않고 설치도 차단돼 있다.

즉 **B5·B6는 "코드가 그렇게 되어 있다"까지만 확인했고, "실제로 그렇게 동작한다"는 확인하지
못했다.** 보고서에 통과로 적었지만 등급이 다르다는 점을 분명히 해둔다.

**하는 법**: `npm run dev` 후 브라우저에서 (a) `.txt` 파일을 선택해 오류가 뜨고 네트워크
요청이 없는지, (b) 결과 화면에서 "다시 분석하기"를 눌러 미리보기까지 사라지는지 확인.
샌드박스 예외가 필요하면 주행 **전에** `/sandbox`에서 열어야 한다.

### 3. 미확인 전제 — Gemini 모델명
`lib/gemini.ts`가 쓰는 모델명 `'gemini-3.6-flash'`는 스프린트 1에서 온 값을 그대로 유지했다.
실제 호출을 하지 않았으므로 **이 모델명이 SDK 0.1.3 경로에서 유효한지 확인하지 못했다.**
스프린트 1이 실제로 동작했다면 문제없다.
