## 스프린트 5: 웹 서비스 배포 (Oracle Cloud Always Free)

- **목표**: 인터넷에서 HTTPS로 접속 가능하고, 카메라가 동작하며, **API 비용이 통제되는** 서비스
- **범위**:
  - **[P0] 비용 방어** — IP당 요청 제한. 공개 URL + 무제한 AI 호출은 곧 요금 폭탄이다
  - **[P0] 프로덕션 구동** — `output: 'standalone'`, 헬스체크, 부팅 시 환경변수 검증
  - **[P0] HTTPS** — nginx 리버스 프록시 + Let's Encrypt. **카메라의 필수 조건**이다
  - **[P0] 자동 재시작** — systemd 유닛. 죽으면 알아서 살아나야 한다
  - **[P0] 배포 런북** — VM 생성부터 실행까지 복붙 가능한 절차
  - [P1] 배포·갱신 스크립트, 로그 확인 절차
- **제외 항목**: 도메인 구매(sslip.io로 시작), CDN, 오토스케일, 사용자 계정, 결제

## 구성 근거

### Sprint 1을 먼저 하는 이유
**위험 검증**: Gemini Pro 2.0이 정말 관상 분석에 적합한가, 응답 시간은 목표에 맞는가를 가장 먼저 확인해야 함. 이게 실패하면 전체 방향을 바꿔야 할 수 있음.

**최소 동작 구현**: 사진 업로드 → 분석 결과까지만 구현하면 핵심 경험을 테스트할 수 있음. 사주 해석까지는 나중에 추가해도 사용자 피드백을 받기에 충분.

**다음 단계를 열어줌**: Sprint 1이 성공하면 Sprint 2에서 결과 품질을 높이고, Sprint 3에서 카메라를 추가할 수 있음.

---

### Sprint 2를 두 번째로 하는 이유
**사주 연관 분석 추가**: 핵심 가치 제안. Sprint 1의 관상 분석 결과를 받아서 사주 해석을 더하면 "재미있는 결과"가 됨.

**오류 처리 필수**: MVP라도 얼굴 미인식 같은 기본 오류는 처리해야 사용 가능한 서비스로 느껴짐.

**UI 개선**: 결과를 보기 좋게 정리하면 사용자 경험이 훨씬 나아짐.

**이후로 미루는 이유**: 저장/공유, 계정 등은 없어도 MVP는 동작함. Sprint 1, 2까지로도 "점을 보는 웹앱"으로서의 완성도가 있음.

---

### Sprint 3은 선택사항
**카메라는 나중에 가능**: 사진 업로드로도 충분히 사용 가능. 사용자 피드백이 "카메라 촬영이 필요하다"고 할 때 추가.

**MVP 출시 후 방향 조정**: Sprint 2까지 완성한 후 실제 반응을 보고, 카메라가 정말 필요한지 판단 후 진행.
